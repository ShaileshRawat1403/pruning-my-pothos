Write It Down or Watch It Guess

After this, you can write the one file a coding agent reads before it touches your project, and know what that file cannot do.

A coding agent starts every session from nothing. It does not remember yesterday, your rules, or the folder you told it never to touch. Many coding agents read one plain file at the start: AGENTS.md, or CLAUDE.md for Claude Code. Write it once and you stop repeating yourself. Write it badly and it follows the bad version, carefully.

The tools, from their own docs

  • AGENTS.md

    For: An open format: one plain file at the root of a repository, described as a README for agents. Its site lists more than twenty tools that read it.

    Does not: Enforcing anything. It is a file the agent reads, nothing more.

    As of 2026-10-01

  • Claude Code (CLAUDE.md)

    For: Read at the start of every session; it can read AGENTS.md instead when there is no CLAUDE.md.

    Does not: Blocking an action. Its docs call these files context, not enforced configuration, and point to hooks for that.

    As of 2026-10-01

  • Cursor

    For: Reads an AGENTS.md in the project root, or project rules in .cursor/rules as .mdc files.

    Does not: Reading a plain .md file inside .cursor/rules. Its docs say that file is ignored.

    As of 2026-10-01

Where this stops

A file is read, not obeyed. Claude Code's own documentation calls these files context, not enforced configuration. Anything that must never happen needs a check that runs outside the agent: a permission it does not have, a branch it cannot push to, a test that fails.
