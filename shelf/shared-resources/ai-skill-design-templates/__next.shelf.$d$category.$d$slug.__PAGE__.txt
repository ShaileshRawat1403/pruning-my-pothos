2:T591,<p>These templates are for the moment when a useful prompt starts repeating often enough that it should become a reusable capability.</p>
<p>The goal is not to create documentation overhead. The goal is to make repeated work clearer, safer, and easier to hand off.</p>
<h2 id="skill-definition-template">Skill definition template</h2>
<pre><code class="language-yaml">name:
objective:
inputs:
constraints:
tools:
output_format:
success_criteria:
failure_modes:
escalation:
</code></pre>
<p>Use this when a repeated task needs a stable contract.</p>
<h2 id="skill-review-template">Skill review template</h2>
<pre><code class="language-yaml">skill_version:
change_summary:
expected_behavior_change:
test_cases:
rollback_note:
</code></pre>
<p>Use this when a skill changes and you want the behavior shift to stay explicit.</p>
<h2 id="skill-composition-template">Skill composition template</h2>
<pre><code class="language-yaml">trigger:
upstream_context:
skill_execution:
output_contract:
downstream_handoff:
</code></pre>
<p>Use this when one skill becomes part of a wider workflow.</p>
