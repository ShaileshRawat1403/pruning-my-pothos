e3:T3238,<p>An Ollama model supports tools when your Ollama server lists <code>tools</code> among that model&#39;s capabilities. The server works this out from the model&#39;s prompt template or its built-in parser, so the answer depends on two things: the Ollama version you run and the version of the model you pulled. The model library&#39;s <a href="https://ollama.com/search?c=tools">Tools filter</a> lists models Ollama labels this way, though not all of them at once.</p>
<p><strong>Checked 18 November 2026</strong> against Ollama&#39;s documentation, its model library and its source code at release v0.40.16 (published 9 November 2026). None of the commands below were run for this page: no Ollama install and no model were tested. The expected results come from the documentation and the source, linked at each step.</p>
<h2 id="check-your-own-install">Check your own install</h2>
<h3 id="1-your-ollama-version">1. Your Ollama version</h3>
<pre><code class="language-bash">ollama --version
curl http://localhost:11434/api/version
</code></pre>
<p><code>ollama --version</code> asks the running server for its version and prints <code>ollama version is</code> followed by it. If the command-line client is a different version, it adds a line starting <code>Warning: client version is</code> (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/cmd/cmd.go#L2349-L2367">source, cmd/cmd.go</a>). The server&#39;s version is the one that matters here, because the server decides the capabilities. The <code>/api/version</code> endpoint returns it as JSON with a <code>version</code> field (<a href="https://docs.ollama.com/api-reference/get-version">API reference</a>).</p>
<h3 id="2-the-models-capabilities">2. The model&#39;s capabilities</h3>
<pre><code class="language-bash">ollama show qwen3
curl http://localhost:11434/api/show -d &#39;{&quot;model&quot;: &quot;qwen3&quot;}&#39;
</code></pre>
<p>Replace <code>qwen3</code> with the model you pulled; <code>qwen3</code> is the model Ollama&#39;s own <a href="https://docs.ollama.com/capabilities/tool-calling">tool calling examples</a> use. <code>ollama show</code> prints a Capabilities table when the server reports any (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/cmd/cmd.go#L1499-L1500">source, cmd/cmd.go</a>). The <code>/api/show</code> endpoint returns the same list in a <code>capabilities</code> array, which the API reference describes as a &quot;List of supported features&quot; (<a href="https://docs.ollama.com/api-reference/show-model-details">API reference</a>).</p>
<p>Look for <code>tools</code> in that list. That is the exact string Ollama uses for tool support (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/types/model/capability.go#L5-L16">source, types/model/capability.go</a>). Other values in the same list include <code>completion</code>, <code>thinking</code>, <code>vision</code> and <code>embedding</code>.</p>
<h3 id="3-a-single-tool-call">3. A single tool call</h3>
<pre><code class="language-bash">curl http://localhost:11434/api/chat -d &#39;{
  &quot;model&quot;: &quot;qwen3&quot;,
  &quot;stream&quot;: false,
  &quot;messages&quot;: [
    {&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: &quot;What is the temperature in New York?&quot;}
  ],
  &quot;tools&quot;: [{
    &quot;type&quot;: &quot;function&quot;,
    &quot;function&quot;: {
      &quot;name&quot;: &quot;get_temperature&quot;,
      &quot;description&quot;: &quot;Get the current temperature for a city&quot;,
      &quot;parameters&quot;: {
        &quot;type&quot;: &quot;object&quot;,
        &quot;required&quot;: [&quot;city&quot;],
        &quot;properties&quot;: {
          &quot;city&quot;: {&quot;type&quot;: &quot;string&quot;, &quot;description&quot;: &quot;The name of the city&quot;}
        }
      }
    }
  }]
}&#39;
</code></pre>
<p>This follows the single-tool request in Ollama&#39;s <a href="https://docs.ollama.com/capabilities/tool-calling">tool calling documentation</a>. What to expect:</p>
<ul>
<li><strong>If the model has the <code>tools</code> capability</strong> and decides to use the tool, the reply&#39;s <code>message</code> carries a <code>tool_calls</code> list, each entry with the function&#39;s <code>name</code> and its <code>arguments</code> (<a href="https://docs.ollama.com/capabilities/tool-calling">docs</a>). Your code runs the function and sends the result back as a message with <code>&quot;role&quot;: &quot;tool&quot;</code>. The model may also answer in plain text without calling the tool; the documentation does not promise a call.</li>
<li><strong>If the model lacks the <code>tools</code> capability</strong>, the server refuses the request with HTTP 400 and an error that names the model and ends in <code>does not support tools</code>. A request that includes tools requires the capability (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/routes.go#L3203-L3206">source, server/routes.go</a>), the check fails when it is missing (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/images.go#L599-L631">server/images.go</a>), the model&#39;s name is put in front of it (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/routes.go#L274-L276">server/routes.go</a>), and the error is returned as a bad request (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/routes.go#L3634-L3637">server/routes.go</a>). The documentation does not describe this error.</li>
</ul>
<h2 id="how-ollama-decides">How Ollama decides</h2>
<p>At v0.40.16 the server adds <code>tools</code> to a model&#39;s capabilities in three cases (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/images.go#L242-L301">source, server/images.go</a>):</p>
<ul>
<li>the model&#39;s Go template uses a <code>tools</code> variable;</li>
<li>the model&#39;s chat template mentions <code>tools</code> or <code>tool_call</code>;</li>
<li>the model uses one of Ollama&#39;s built-in parsers that handles tool calls (<a href="https://github.com/ollama/ollama/blob/d63b702609c4300a2ca07be2bdb0adb9834725e5/server/images.go#L486-L497">source</a>).</li>
</ul>
<p>So the capability is read from files that arrive with the model and from parsers that ship with Ollama. Two consequences follow from that, and both are worth checking yourself: a copy of a model pulled long ago carries the template it was pulled with, and the list of built-in parsers belongs to the Ollama version you run.</p>
<h2 id="what-the-label-leaves-open">What the label leaves open</h2>
<p><code>tools</code> means the server will accept a <code>tools</code> array for that model and look for tool calls in its output. It says nothing about how well the model picks a tool or fills its arguments. That takes a test with your own tools and prompts.</p>
<p>Ollama&#39;s documentation also covers <a href="https://docs.ollama.com/capabilities/tool-calling">streaming tool calls, parallel tool calls and a multi-turn agent loop</a>. For what a tool call is and what can go wrong when language triggers an action, see <a href="/systems/tool-use-when-language-triggers-actions/">Tool use: when language triggers actions</a>.</p>
<h2 id="what-the-librarys-tools-filter-showed-on-18-november-2026">What the library&#39;s Tools filter showed on 18 November 2026</h2>
<p>The table below is an observed list: what the <a href="https://ollama.com/search?c=tools">Tools filter</a> showed when it was read on 18 November 2026. It is incomplete, and it changes with the sort order and over time.</p>
<ul>
<li><strong>It shows 20 models and no total.</strong> Neither sort order offered a next page or a count.</li>

</ul>
