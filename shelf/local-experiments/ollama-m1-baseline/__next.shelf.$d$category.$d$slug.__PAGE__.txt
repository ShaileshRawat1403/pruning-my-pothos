<h2 id="what-happened">What happened</h2>
<p>Short runs were fast. Long runs slowed down. Once I logged temperatures, the pattern was obvious: the system throttled after a few minutes, and the numbers became incomparable.</p>
<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>time</strong>. If you test too long, you stop testing the model and start testing heat dissipation.</p>
<p>The second gate is <strong>consistency</strong>. Without a fixed prompt and a fixed run length, the baseline drifts even when nothing else changes.</p>
<h2 id="setup-walkthrough">Setup walkthrough</h2>
<ol>
<li>Pick one model and one prompt.</li>
<li>Run the prompt in short bursts to avoid thermal drift.</li>
<li>Log run time and system temperature together.</li>
</ol>
<h2 id="first-time-config">First-time config</h2>
<pre><code class="language-bash">export OLLAMA_HOST=&quot;http://127.0.0.1:11434&quot;
export OLLAMA_MODEL=&quot;llama3.1:8b&quot;
</code></pre>
<aside class="callout">
  <p><strong>Guiding rule.</strong> Your first baseline is only valid for the temperature window you measured.</p>
</aside>
<h2 id="quick-checks">Quick checks</h2>
<pre><code class="language-bash">ollama run llama3.1:8b &quot;ping&quot;
</code></pre>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Long runs hide throttling until you compare a later test.</li>
<li>Background apps push the host into a hotter state.</li>
<li>Changing the prompt changes the performance profile.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>I treated the baseline as a short, repeatable ritual and logged the host temperature alongside the timing. That made later comparisons honest.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would automate a short benchmark loop, record system temperature per run, and stop the test before the host warms up.</p>
