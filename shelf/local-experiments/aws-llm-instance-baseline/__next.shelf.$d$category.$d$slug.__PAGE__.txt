<h2 id="what-happened">What happened</h2>
<p>My first run failed even with valid keys. The issue was not the model. It was a security group rule that blocked the inbound port and a missing IAM permission that made the instance look healthy but unusable.</p>
<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>IAM</strong>. If the role is wrong, you can see the instance but cannot use it.</p>
<p>The second gate is <strong>networking</strong>. Security groups block traffic by default; your app must be explicitly allowed.</p>
<h2 id="portal-walkthrough">Portal walkthrough</h2>
<ol>
<li>Create a VPC or reuse the default one for the first pass.</li>
<li>Launch a GPU instance and attach a minimal IAM role.</li>
<li>Open the inbound port for your app and database access.</li>
<li>Create a Postgres instance inside the same VPC.</li>
<li>Collect the endpoint, key, and host values for config.</li>
</ol>
<h2 id="first-time-config">First-time config</h2>
<pre><code class="language-bash">export LLM_HOST=&quot;http://&lt;instance-ip&gt;:&lt;port&gt;&quot;
export DATABASE_URL=&quot;postgresql://&lt;user&gt;:&lt;password&gt;@&lt;db-hostname&gt;:5432/&lt;db-name&gt;&quot;
</code></pre>
<aside class="callout">
  <p><strong>Guiding rule.</strong> If you cannot describe the VPC boundary, you will debug the wrong layer.</p>
</aside>
<h2 id="quick-checks">Quick checks</h2>
<pre><code class="language-bash">nc -vz &lt;instance-ip&gt; &lt;port&gt;
psql &quot;postgresql://&lt;user&gt;:&lt;password&gt;@&lt;db-hostname&gt;:5432/&lt;db-name&gt;&quot;
</code></pre>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>IAM role looks correct but lacks the specific service permission.</li>
<li>Security group allows the port but the instance subnet is private.</li>
<li>Using a different region for the database adds invisible latency.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>I treated IAM and security groups as first-class parts of the architecture, not afterthoughts. Once those gates were clear, the rest was predictable.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would pin the AMI, keep everything in a single region, and log network rules alongside app config.</p>
