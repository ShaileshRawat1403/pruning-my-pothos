2:T34e7,<h2 id="the-command-in-short">The command, in short</h2>
<p><code>ollama launch</code> sets up a coding tool to use an Ollama model and starts it, with no environment variables or config files to write. It needs Ollama 0.15 or later, per the <a href="https://ollama.com/blog/launch">launch announcement</a>.</p>
<pre><code class="language-bash">ollama launch                          # pick a tool, then a model, from a menu
ollama launch codex                    # start one integration directly
ollama launch claude --model qwen3.5   # choose the model as well
ollama launch droid --config           # configure it without starting it
</code></pre>
<p>The integrations listed in <a href="https://docs.ollama.com/cli">Ollama&#39;s CLI docs</a>, checked 2026-10-21: OpenCode, Claude Code, Codex, VS Code and Droid (Factory&#39;s coding agent). The tool has to be installed first; the launcher tells you when it is not. For coding work, the announcement recommends raising Ollama&#39;s context length to at least 64000 tokens.</p>
<h2 id="opencode-with-a-local-model">OpenCode with a local model</h2>
<p><strong>Checked 20 November 2026</strong> against Ollama&#39;s and OpenCode&#39;s documentation and OpenCode&#39;s source. Nothing in this section was run for this page, and the first run further down used Codex, so none of it is tested here.</p>
<p>Which OpenCode you install decides how it finds Ollama. Two release lines were current on that date:</p>
<ul>
<li><strong>OpenCode 1</strong> (1.19.6, released 17 November 2026) is what <code>curl -fsSL https://opencode.ai/install | bash</code> and <code>npm install -g opencode-ai</code> install. The <a href="https://opencode.ai/install">install script</a> says it &quot;only installs OpenCode 1&quot;, and npm&#39;s <code>latest</code> tag pointed to 1.19.6. Its docs are at <a href="https://opencode.ai/v1/docs/providers">opencode.ai/v1/docs</a>.</li>
<li><strong>OpenCode 2</strong> (2.3.2, released 18 November 2026) has its own installer, <code>curl -fsSL https://opencode.ai/v2/install | bash</code>, named in the same script. The main <a href="https://opencode.ai/docs/providers">opencode.ai/docs</a> pages describe it. See the <a href="https://github.com/anomalyco/opencode/releases">release list</a>.</li>
</ul>
<h3 id="the-short-way-ollama-launch">The short way: ollama launch</h3>
<pre><code class="language-bash">ollama launch opencode           # set OpenCode up for Ollama and start it
ollama launch opencode --config  # set it up without starting it
</code></pre>
<p>Ollama&#39;s <a href="https://docs.ollama.com/integrations/opencode">OpenCode page</a> says this does not overwrite <code>~/.config/opencode/opencode.json</code>, so existing OpenCode settings still apply, and that models defined only in that file do not appear in the launch picker. <code>ollama launch</code> needs Ollama 0.15 or later.</p>
<h3 id="by-hand-opencode-1">By hand, OpenCode 1</h3>
<p>Add a provider to OpenCode&#39;s config, <code>~/.config/opencode/opencode.json</code>:</p>
<pre><code class="language-json">{
  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,
  &quot;provider&quot;: {
    &quot;ollama&quot;: {
      &quot;npm&quot;: &quot;@ai-sdk/openai-compatible&quot;,
      &quot;name&quot;: &quot;Ollama&quot;,
      &quot;options&quot;: { &quot;baseURL&quot;: &quot;http://localhost:11434/v1&quot; },
      &quot;models&quot;: { &quot;qwen3.5&quot;: { &quot;name&quot;: &quot;qwen3.5&quot; } }
    }
  }
}
</code></pre>
<p>This is the shape both <a href="https://docs.ollama.com/integrations/opencode">Ollama&#39;s OpenCode page</a> and <a href="https://opencode.ai/v1/docs/providers">OpenCode 1&#39;s provider docs</a> show. Each key under <code>models</code> is a model name as <code>ollama list</code> shows it. Start <code>opencode</code> and pick the model with <code>/models</code>.</p>
<h3 id="opencode-2-finds-ollama-by-itself">OpenCode 2 finds Ollama by itself</h3>
<p>With Ollama running on the same machine, OpenCode 2 probes <code>http://127.0.0.1:11434</code> and adds the models it finds to <code>/models</code> without any config, per its <a href="https://opencode.ai/docs/providers">provider docs</a>. At 2.3.2 the <a href="https://github.com/anomalyco/opencode/blob/c0ad18b402eb2827fc1ee71c171b1177b3fc02d1/packages/core/src/plugin/provider/ollama.ts#L44-L90">source</a> reads Ollama&#39;s model list and each model&#39;s details, keeps the models that report the <code>completion</code> capability, and marks tool support from the <code>tools</code> capability: the same list explained in <a href="/shelf/shared-resources/which-ollama-models-support-tools/">Which Ollama models support tools</a>. For an Ollama server elsewhere, the docs set <code>providers.ollama.settings.baseURL</code>, ending in <code>/v1</code>. To make a model the default, set <code>&quot;model&quot;: &quot;ollama/&lt;name&gt;&quot;</code> (<a href="https://opencode.ai/docs/models">models docs</a>).</p>
<h3 id="context-length-is-where-it-breaks">Context length is where it breaks</h3>
<p>Ollama&#39;s default context depends on GPU memory: 4k tokens below 24 GiB of VRAM, 32k from 24 to 48 GiB, and 256k at 48 GiB or more (<a href="https://docs.ollama.com/context-length">context length docs</a>). The two projects give different numbers for what OpenCode needs:</p>
<ul>
<li>Ollama&#39;s OpenCode page: &quot;a context length of 64k or higher&quot;.</li>
<li>OpenCode 1&#39;s provider docs: if tool calls are not working, raise Ollama&#39;s <code>num_ctx</code>, starting around 16k to 32k.</li>
</ul>
<p>Set it with the slider in the Ollama app&#39;s settings, or start the server with <code>OLLAMA_CONTEXT_LENGTH=64000 ollama serve</code>. <code>ollama ps</code> shows the context a loaded model is running with. A longer context needs more memory: Ollama&#39;s <a href="https://ollama.com/blog/launch">launch post</a> gives about 23 GB of VRAM for <code>glm-4.7-flash</code> at 64000 tokens.</p>
<p>OpenCode 2 takes a model&#39;s context size from the model&#39;s own details (<a href="https://github.com/anomalyco/opencode/blob/c0ad18b402eb2827fc1ee71c171b1177b3fc02d1/packages/core/src/plugin/provider/ollama.ts#L86-L88">source</a>). That is the size the model supports, which can be larger than the context your Ollama server is set to serve.</p>
<h3 id="not-tested-here">Not tested here</h3>
<p>A tested result would record the Ollama and OpenCode versions, the model and tag, the operating system, the exact commands and output, the date, and who ran it.</p>
<h2 id="the-first-run-january-2026">The first run, January 2026</h2>
<p>The rest of this page is the first run, from January 2026: what the flow looked like, the two places it stops, and what fixed them.</p>
<blockquote>
<p><strong>Key takeaways</strong></p>
<ul>
<li><code>ollama launch</code> turns model selection into a single handoff step.</li>
<li>The integration list is the contract: install the tool before you launch it.</li>
<li>A short, visible flow beats hidden config when you are new to local stacks.</li>
</ul>
</blockquote>
<p>This experiment is about a new entry point: <code>ollama launch</code>. Instead of wiring a tool to a model by hand, the launcher asks which integration you want and then routes the model into it. The result feels like a simple handoff layer for local AI tools.</p>

<h2 id="what-happened">What happened</h2>
<p>The flow started with a simple command and a menu. The launcher listed available integrations (Claude, Codex, OpenCode, and others), then asked for a model. When I selected Codex without having it installed, the launcher surfaced the missing dependency clearly and told me what to install.</p>

<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>tool installation</strong>. If the integration is not installed, the launcher stops and tells you exactly what is missing.</p>
<p>The second gate is <strong>model availability</strong>. If the model is not local, the handoff stalls until it is pulled or selected.</p>
<h2 id="setup-walkthrough">Setup walkthrough</h2>
<ol>
<li>Run the launcher.</li>
<li>Select an integration (Codex, OpenCode, or another tool you have installed).</li>
<li>Select a local model.</li>
<li>Start the tool session.</li>
</ol>
<pre><code class="language-bash">ollama launch
</code></pre>
<h2 id="first-time-config">First-time config</h2>
<p>When Codex was missing, the launcher pointed to the installation command. After installing, the same launch flow worked cleanly.</p>
<pre><code class="language-bash">npm install -g @openai/codex
</code></pre>

<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Launching a tool before it is installed.</li>
<li>Selecting a model that is not available locally.</li>
<li>Assuming the launcher is a model manager rather than a handoff layer.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>The launcher compresses setup into one visible decision tree. Instead of hunting for flags and configs, you pick a tool and a model and move on.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would pre-install the integrations I care about, then treat <code>ollama launch</code> as the default entry point for local tool sessions.</p>
