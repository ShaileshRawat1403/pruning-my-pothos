<h2 id="what-happened">What happened</h2>
<p>The install looked easy and it was. The failure showed up later: a model name mismatch, a stalled pull, and thermal throttling after a long run. Each issue felt minor, but they compounded into unstable baselines.</p>
<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>model identity</strong>. If the model name in your prompt runner does not match the local registry, the request fails or pulls the wrong thing.</p>
<p>The second gate is <strong>host capacity</strong>. Local runs are bounded by RAM, VRAM, and heat. Even on a good machine, long runs will drift if the system throttles.</p>
<h2 id="setup-walkthrough">Setup walkthrough</h2>
<ol>
<li>Install Ollama and verify the CLI is present.</li>
<li>Pull one model and run a single prompt to confirm the runtime.</li>
<li>Keep the first run small. Your goal is a stable baseline, not speed.</li>
</ol>
<h2 id="first-time-config">First-time config</h2>
<p>I pinned the model and forced explicit names in config so I did not guess later.</p>
<pre><code class="language-bash">export OLLAMA_HOST=&quot;http://127.0.0.1:11434&quot;
export OLLAMA_MODEL=&quot;llama3.1:8b&quot;
</code></pre>
<aside class="callout">
  <p><strong>Guiding rule.</strong> If the model name is not explicit, the test result is not reliable.</p>
</aside>
<h2 id="quick-checks">Quick checks</h2>
<pre><code class="language-bash">ollama list
ollama run llama3.1:8b &quot;ping&quot;
</code></pre>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Model name in code does not match the local registry.</li>
<li>The first run pulls a large model and stalls without feedback.</li>
<li>Thermal throttling changes latency after a few minutes.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>I locked the model name, measured the first five runs only, and recorded machine state while the fan curve was stable. That turned the baseline into something I could compare later.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would script the baseline run from the start, capture system temperature in the log, and freeze the model version before testing anything else.</p>
