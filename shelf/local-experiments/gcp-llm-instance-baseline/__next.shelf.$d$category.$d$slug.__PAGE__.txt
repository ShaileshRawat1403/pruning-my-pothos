<h2 id="what-happened">What happened</h2>
<p>The instance was live, but my app could not reach it. The firewall rule existed, but it was attached to the wrong network tag. The result looked like a code bug, but it was not.</p>
<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>IAM</strong>. If the account does not have the right permissions, the service looks available but fails on use.</p>
<p>The second gate is <strong>firewall rules</strong>. The rule has to match the instance tags and the network you actually use.</p>
<h2 id="portal-walkthrough">Portal walkthrough</h2>
<ol>
<li>Create a new GCP project for this experiment.</li>
<li>Enable the compute and AI services you need.</li>
<li>Create a GPU instance with a single, known image.</li>
<li>Add a firewall rule for the port you will hit.</li>
<li>Create the database and keep it in the same region.</li>
</ol>
<h2 id="first-time-config">First-time config</h2>
<pre><code class="language-bash">export LLM_HOST=&quot;http://&lt;instance-ip&gt;:&lt;port&gt;&quot;
export DATABASE_URL=&quot;postgresql://&lt;user&gt;:&lt;password&gt;@&lt;db-hostname&gt;:5432/&lt;db-name&gt;&quot;
</code></pre>
<aside class="callout">
  <p><strong>Guiding rule.</strong> In GCP, if the project is wrong, everything downstream is wrong.</p>
</aside>
<h2 id="quick-checks">Quick checks</h2>
<pre><code class="language-bash">nc -vz &lt;instance-ip&gt; &lt;port&gt;
psql &quot;postgresql://&lt;user&gt;:&lt;password&gt;@&lt;db-hostname&gt;:5432/&lt;db-name&gt;&quot;
</code></pre>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Firewall rule exists but does not match the instance tag.</li>
<li>Services are not enabled on the project.</li>
<li>Database lives in a different region than the instance.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>I treated project setup as an architectural decision, not a form. Once the project, IAM, and firewall rules aligned, the rest of the setup behaved.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would verify project services first, pin the instance image, and keep every resource in one region.</p>
