<h2 id="what-happened">What happened</h2>
<p>Quality held up through the middle range, then bent. Past a threshold, summaries became vague and citations started drifting. The model still responded, but the answers softened.</p>
<h2 id="the-two-gates">The two gates</h2>
<p>The first gate is <strong>retrieval fit</strong>. If the context is already noisy, adding more text does not help.</p>
<p>The second gate is <strong>attention budget</strong>. Past a point, the model spends more effort tracking tokens than answering the question.</p>
<h2 id="experiment-walkthrough">Experiment walkthrough</h2>
<ol>
<li>Fix a small, representative document set.</li>
<li>Keep the prompt constant across runs.</li>
<li>Increase context in steps and score the output.</li>
</ol>
<h2 id="first-time-config">First-time config</h2>
<pre><code class="language-bash">export OLLAMA_MODEL=&quot;llama3.1:8b&quot;
export CONTEXT_STEPS=&quot;4k,8k,16k,32k&quot;
</code></pre>
<aside class="callout">
  <p><strong>Guiding rule.</strong> If you change more than one variable, the result stops being a signal.</p>
</aside>
<h2 id="quick-checks">Quick checks</h2>
<pre><code class="language-bash">ollama run llama3.1:8b &quot;summarize the document set&quot;
</code></pre>
<h2 id="failure-modes">Failure modes</h2>
<ul>
<li>Changing the document set between runs hides the drift.</li>
<li>Adding context without scoring quality gives false confidence.</li>
<li>Overfitting the prompt to one test case.</li>
</ul>
<h2 id="what-made-the-difference">What made the difference</h2>
<p>I fixed the dataset and prompt, then focused on the slope where quality started to bend. That gave me a usable boundary.</p>
<h2 id="what-i-would-do-next-time">What I would do next time</h2>
<p>I would add a small human rubric and track a single quality score per step to make the curve explicit.</p>
