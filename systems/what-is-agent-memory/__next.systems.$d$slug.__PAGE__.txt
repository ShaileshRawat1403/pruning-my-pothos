24:T55f,<p>An agent that greets you by name next week did not remember you. After this conversation something wrote your name into storage, and before the next one something put it back into the model&#39;s input. That writing and reading is agent memory.</p>
<p><strong>The model keeps nothing between calls; an application stores information outside it and places selected parts back into a later run.</strong> Everything an agent appears to remember arrives the same way as everything else it sees: in the <a href="/systems/context-windows-as-working-memory/">context window</a> for the current run.</p>
<h2 id="short-term-and-long-term-memory">Short-term and long-term memory</h2>
<p><strong>LangChain&#39;s documentation describes short-term memory as thread-scoped, kept as part of the agent&#39;s state and saved through checkpoints.</strong> In practice that is the conversation so far, plus anything the agent has worked out within the same thread or session. It still has to fit in the context window, so long threads are trimmed or summarised, and whatever is cut is gone from the run.</p>
<p><strong>Long-term memory is shared across threads and kept outside any single conversation, in what LangChain calls namespaces in a store.</strong> This is the part people usually mean by persistent memory: it survives the end of a session and can be read back in a new one.</p>

<p>Something has to choose what is worth keeping. <strong>Memory can be written while the agent is responding, which LangChain calls the hot path, or afterwards as a background task.</strong> Writing on the hot path makes the memory available at once and slows the response; writing in the background keeps the response quick and the memory arrives later.</p>
<p>Sometimes the model makes the choice through a tool. <strong>Anthropic&#39;s memory tool lets Claude store files under a /memories directory and read them back in later conversations, and it runs client-side: Claude requests the file operations and the application carries them out.</strong> <strong>With the tool enabled, Claude checks its memory directory before starting a task.</strong> The model proposes what to write; the application decides where it lives and whether the write happens at all, the same split an <a href="/systems/what-is-an-agent-harness/">agent harness</a> makes for every other action.</p>
<p>Reading memory back is a selection problem. A store that has grown for months holds more than one run can use, so the application picks the items that belong in this run, the same choice <a href="/systems/retrieval-augmented-generation-in-plain-terms/">retrieval-augmented generation</a> makes for documents. <strong>MemGPT, a 2023 research system, manages memory in tiers, drawing on how operating systems move data between fast and slow memory.</strong> The model&#39;s input is the fast tier; storage is the slow one; something has to move items between them.</p>
<h2 id="what-goes-wrong">What goes wrong</h2>
<p>Memory fails in ordinary ways, because it is ordinary data.</p>
<ul>
<li><strong>Stale:</strong> the user changed their preference, and the old fact is still read back.</li>
<li><strong>Wrong:</strong> the agent wrote down a misunderstanding, and every later run inherits it as context.</li>
<li><strong>Unscoped:</strong> memory saved for one user or project is read into another one&#39;s run.</li>
<li><strong>Planted:</strong> text the agent stored from a web page or a document returns in a later run looking like trusted context.</li>
<li><strong>Out of bounds:</strong> <strong>Anthropic&#39;s documentation warns that a path such as /memories/../../secrets.env can reach files outside the memory directory, so the application has to check every path.</strong></li>
</ul>
<p><strong>Because memory lives in ordinary storage, it can be inspected, corrected and deleted, and it needs the same scoping and review as any other data the system keeps.</strong></p>
<h2 id="what-this-changes">What this changes</h2>
<p>When an agent seems to forget, look at what was written and what was read back into the run before blaming the model. When it remembers something wrong, there is a record to find and delete. And when an agent hands work to the next session on purpose, a written <a href="/systems/agent-instructions-and-handoff-as-an-operating-system/">handoff</a> is memory with a name on it: chosen, dated and readable by a person.</p>
