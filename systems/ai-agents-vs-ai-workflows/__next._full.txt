1e1:T5c9,<p>The word agent now covers a chatbot with memory, a script that calls three tools in order, and a system that plans its own work. That range makes the word useless for deciding anything, which matters because the underlying choice is real and has consequences.</p>
<p>There is one question that separates the cases.</p>
<h2 id="who-chooses-the-next-step">Who chooses the next step</h2>
<p><strong>The essential difference between an AI workflow and an AI agent is who chooses the next step.</strong></p>
<p>In a <strong>workflow</strong>, your program holds the sequence. The model might classify a ticket, extract fields from a document or draft a reply, and when it finishes, your code decides what happens next. If step two succeeds, go to step three. If it fails, take the fallback you wrote. The model does work inside the steps; it does not choose them.</p>
<p>In an <strong>agent-like</strong> system, the model gets a goal and some freedom over what to do next. It looks at what came back from the last step and picks the next one: try a different search, call another tool, ask a question, stop.</p>
<p>Notice what the distinction is not about. It is not about tool use, because a workflow can call plenty of tools. It is not about how capable the model is. It is a fact about your program.</p>
<p><strong>Tool use asks whether the model can request an action. Agent-like behaviour asks whether the model can decide which action or step should happen next.</strong></p>

<h2 id="what-each-one-is-good-at">What each one is good at</h2>
<p>A workflow&#39;s advantage is that you can enumerate what it does. Every path was written by someone, so every path can be tested, reviewed as a diff, and reasoned about before it runs. When it fails it fails at an identifiable step. The cost is rigidity: an input that falls outside the branches you anticipated either stops or goes to a person.</p>
<p>Agent-like freedom earns its place when the path genuinely cannot be written in advance. Investigating why something broke, researching across sources where each answer changes the next question, working through an ambiguous request: in these, the next step depends on what the last one returned, and enumerating the possibilities beforehand is not realistic.</p>
<p>The cost is the same property viewed from the other side. Once the model selects steps, the set of possible runs is larger than you can enumerate, so you cannot review it as a list of paths. Failures become harder to reproduce, and cost and latency stop being predictable.</p>

<p>A useful habit: grant freedom at the smallest scope that solves the problem. Freedom over which of four tools to use is a different proposition from freedom over what the whole task should be.</p>
<h2 id="what-this-does-not-settle">What this does not settle</h2>
<p>Deciding the model may choose the next step says nothing about what it is allowed to do when it chooses. Those are separate questions, and the freedom to select a step is not the same as permission to perform it.</p>
<p>What happens between a chosen step and a real effect is <a href="/systems/from-agent-intent-to-governed-execution/">from agent intent to governed execution</a>.</p>
