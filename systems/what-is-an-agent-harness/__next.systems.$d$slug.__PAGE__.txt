1e:T46e,<p>A language model on its own takes text in and gives text out. It cannot open a file, run a test or remember what it did ten minutes ago. Every coding agent that does those things has software around the model doing them. That software is the agent harness.</p>
<p><strong>An agent harness is the software around a language model that turns it into an agent.</strong> It runs the loop, holds the tools, decides what the model sees and enforces the limits. <strong>The model proposes the next step; the harness decides what actually happens.</strong></p>
<h2 id="the-four-parts">The four parts</h2>
<p>The term is used loosely, so a definition helps. <strong>A 2026 paper defines an agent harness as the runtime engineering layer that wraps one or more language models and turns them into an agent.</strong> <strong>The paper names four conditions: an agent loop that interleaves reasoning, action and observation; tools that can change an external environment; context management that decides what enters and leaves the model&#39;s context; and at least one control that does not depend on the model&#39;s cooperation.</strong></p>

<p>In plain terms:</p>
<ul>
<li><strong>The loop.</strong> The model suggests a step, the harness carries it out, shows the model the result and asks for the next one, until the task is done or a limit stops it. A chat window answers once; a harness keeps going.</li>
<li><strong>The tools.</strong> Reading files is not enough. A tool that writes a file, runs a command or calls a service changes something outside the model. How tools are offered to a model is on <a href="/systems/tool-use-when-language-triggers-actions/">tool use</a>.</li>
<li><strong>The context.</strong> A model only knows what is in its <a href="/systems/context-windows-as-working-memory/">context window</a> on this turn. The harness chooses what goes in: the instructions, the relevant files, the last tool result, a summary of earlier turns.</li>
<li><strong>The controls.</strong> At least one limit is enforced by code, whatever the model writes: a permission prompt, a directory it cannot leave, a budget, a test that must pass. A limit written into the prompt is a request; a limit in the harness is a <a href="/systems/what-is-bounded-autonomy/">bound</a>.</li>
</ul>

<p>The model appears once in that sequence. The other four steps are the harness&#39;s. When an agent does something unexpected, those four steps are where to look first: what it was shown, which tools it had, which limit was missing, and what it kept from the last turn. The longer version of that argument is <a href="/systems/runtime-over-model-why-orchestration-is-the-product/">why the loop outlives the model</a>.</p>
<h2 id="examples">Examples</h2>
<p><strong>The paper tests its definition against Claude Code, Codex CLI, Aider, Cline, OpenHands and SWE-agent.</strong> Each pairs a model with a loop, file and shell tools, context handling and some form of approval.</p>
<p>Harnesses are also sold as parts. <strong>Anthropic&#39;s documentation says the Agent SDK gives developers the same tools, agent loop and context management that power Claude Code.</strong> <strong>Anthropic calls its Claude Agent SDK a general-purpose agent harness.</strong></p>
<p>Context management is where harness design gets interesting on long tasks, because no context window holds a week of work. <strong>For long tasks, Anthropic&#39;s harness has the first session set up the environment and every later session make incremental progress, leaving a progress file, a feature list and git commits for the next session to read.</strong> The model forgets between sessions; the harness writes things down so the next session can pick up.</p>
<p>A harness can also sit around other harnesses. <strong>DAX&#39;s README describes a deterministic runtime contract around stochastic model execution, with a policy crate that evaluates tool requests against policy with no model call.</strong> It runs coding agents such as Claude Code or Codex CLI in a disposable checkout and keeps scope enforcement for itself. DAX is built by this site&#39;s author; its page is on the <a href="/stack/dax/">Stack</a>.</p>
<h2 id="what-a-harness-is-not">What a harness is not</h2>
<p>Several neighbouring terms get used for the same thing. <strong>By the paper&#39;s test, a framework composes agents above the harness, an SDK that has no runtime loop is a set of building blocks, and an eval harness measures results after the task ends.</strong> The older meaning of harness, a test harness that runs code under controlled conditions, survives in that last one.</p>
<p>Names drift between vendors, so test the thing: does it run a loop, act through tools, manage context and enforce at least one limit by itself? If all four, it is a harness, whatever the product page calls it.</p>
<h2 id="what-this-changes">What this changes</h2>
<p>Choosing an agent means choosing a harness as much as a model: which tools it offers, what it shows the model, where it asks a person and what it records. Comparing models inside one harness tells you about the models. Comparing two agents tells you about two models and two harnesses at once, and the harness is the part you can change.</p>
