<h3 id="what-is-the-i-7-cognitive-loop">What is the I-7 cognitive loop?</h3>
<p>The I-7 cognitive loop is a human-computer interaction (HCI) framework designed for builders and designers of AI systems. It extends Donald Norman&#39;s classic stages of action to account for the unique characteristics of non-deterministic, agentic software. Rather than treating interaction as direct manipulation (like clicking buttons), the I-7 loop defines how humans delegate intent, monitor agent execution, and intervene when behavior diverges from policy.</p>
<p>Norman remains the foundation. The seven stages of action still describe how people form goals, act, and evaluate outcomes. The difference is that modern AI systems can reason, choose tools, and execute intermediate steps on their own. I-7 is an advanced layer for this environment: the age of AI-assisted development, where human judgment stays central.</p>
<p>In practice, <span class="highlight">clarity at boundaries reduces downstream errors</span> more than late-stage tuning.</p>

<h2 id="act-i-the-shift">Act I: The shift</h2>
<h3 id="why-norman-needs-an-extension">Why Norman needs an extension</h3>
<p>Norman’s model was shaped around tools where execution was explicit and deterministic. You click, the system does the exact action, and you compare the result.</p>
<p>Agentic systems change that middle layer. Between intent and output, there is now hidden reasoning, retrieval, tool calls, and probabilistic generation. That creates a practical gap: users can still state goals, but they cannot safely trust execution unless reasoning and control points are visible.</p>
<p>The I-7 loop addresses that gap by inserting operational checkpoints before, during, and after execution.</p>

<h3 id="the-i-7-loop">The I-7 loop</h3>
<p>I-7 runs as a repeatable control cycle:</p>
<ul>
<li>Intent -&gt; Inform -&gt; Interpret -&gt; Initiate -&gt; Inspect -&gt; Intervene -&gt; Iterate</li>
</ul>
<p>The value is not the labels alone. The value is that each label marks a decision point where responsibility is explicit.</p>

<h2 id="act-ii-the-seven-phases">Act II: The seven phases</h2>
<h3 id="intent">Intent</h3>
<p>Intent is the contract. It defines role, task, boundaries, and failure conditions.</p>
<p>If skipped: the system optimizes for fluency over correctness.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> &quot;Refactor this module without changing the public API.&quot;</li>
<li><strong>Product manager:</strong> &quot;Draft a v1 PRD for onboarding with scope limits and non-goals.&quot;</li>
<li><strong>Researcher:</strong> &quot;Summarize only claims directly supported by cited sources.&quot;</li>
</ul>
<h3 id="inform">Inform</h3>
<p>Inform is context governance. You choose what evidence the system may use.</p>
<p>If skipped: low-signal context causes plausible but ungrounded outputs.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> provide failing tests, target files, and logs.</li>
<li><strong>Product manager:</strong> provide interview notes, key metrics, and constraints.</li>
<li><strong>Researcher:</strong> provide canonical papers and explicit exclusions.</li>
</ul>
<h3 id="interpret">Interpret</h3>
<p>Interpret is pre-execution alignment. The system states plan and assumptions in plain language.</p>
<p>If skipped: users discover misalignment only after execution side effects.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> ask for a step plan before file edits.</li>
<li><strong>Product manager:</strong> ask for trade-off framing before writing.</li>
<li><strong>Researcher:</strong> ask for hypothesis and evidence chain before synthesis.</li>
</ul>
<h3 id="initiate">Initiate</h3>
<p>Initiate is guarded execution. Actions should pass schema and policy checks.</p>
<p>If skipped: malformed tool calls and unsafe actions move into runtime.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> patch only after diff preview and lint/test gate.</li>
<li><strong>Product manager:</strong> ticket creation only after required fields validate.</li>
<li><strong>Researcher:</strong> data queries only after schema and source checks pass.</li>
</ul>
<h3 id="inspect">Inspect</h3>
<p>Inspect is output verification against evidence and acceptance criteria.</p>
<p>If skipped: hallucinations and logic drift become part of the baseline.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> verify tests, type checks, and behavior diffs.</li>
<li><strong>Product manager:</strong> verify PRD traceability to source interviews.</li>
<li><strong>Researcher:</strong> verify every claim maps to a source fragment.</li>
</ul>
<h3 id="intervene">Intervene</h3>
<p>Intervene is explicit human authority to pause, redirect, or reject.</p>
<p>If skipped: autonomy scales faster than accountability.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> block migration without rollback proof.</li>
<li><strong>Product manager:</strong> stop launch when success metrics are ambiguous.</li>
<li><strong>Researcher:</strong> halt conclusions where evidence conflicts remain unresolved.</li>
</ul>
<h3 id="iterate">Iterate</h3>
<p>Iterate turns corrections into reusable system memory: tests, prompts, policies, and examples.</p>
<p>If skipped: the same errors recur in new language.</p>
<p>Examples:</p>
<ul>
<li><strong>Developer:</strong> convert incident fixes into regression tests.</li>
<li><strong>Product manager:</strong> convert review feedback into template constraints.</li>
<li><strong>Researcher:</strong> convert corrected citations into a retrieval benchmark set.</li>
</ul>
<h2 id="act-iii-using-the-loop">Act III: Using the loop</h2>
<h3 id="ai-assisted-not-ai-generated">AI-assisted, not AI-generated</h3>
<p>I-7 is designed for AI-assisted development. The system contributes speed and synthesis; the human owns intent, judgment, and accountability.</p>
<h3 id="a-practical-run-loop">A practical run loop</h3>
<p>Use this five-minute loop in any agent workflow:</p>
<ol>
<li>Write Intent in one sentence (role, task, boundary).</li>
<li>Attach only required context for the task.</li>
<li>Ask for plan and assumptions before execution.</li>
<li>Run with explicit guardrails and inspect outputs.</li>
<li>Save one correction as a reusable artifact.</li>
</ol>
